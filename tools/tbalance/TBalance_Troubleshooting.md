# TBalance Troubleshooting Notes

作成日: 2026-08-13

## 画像OKなのにキャンバス上で見えない

### 症状

- レイヤー一覧のサムネイルには画像が表示される。
- キャンバス上では選択枠だけが表示され、画像本体が見えない。
- 背景を非表示にしても画像が出ない。
- 下部ステータスには `画像OK: 読み込み元あり / 512x512` のように表示される。

### 見分け方

下部ステータスの診断表示を確認する。

例:

```text
画像OK: 読み込み元あり / 512x512 / op:0 disp:block clip:none
```

判断:

- `読み込み元あり` かつ自然サイズが出ている場合、リンク切れではない。
- `disp:block` なら非表示指定ではない。
- `clip:none` ならマスクや切り抜きではない。
- `op:0` ならレイヤー本体が完全透明になっている。

### 原因

今回の原因は、画像レイヤーに設定された「動き・演出」のアニメーションだった。

fadeIn / zoomIn / slideIn などは開始状態で `opacity: 0` になる。編集画面でその開始状態のまま止まると、画像本体だけが見えず、選択枠だけ表示される。

### 対処

編集画面ではレイヤーのアニメーションを無効化し、常に見える状態にする。

実装方針:

- 編集中 (`edit: true`) は `applyAnimationStyle` で animation を設定しない。
- CSS側でも、プレビューではないキャンバスでは `.tb-layer` の animation を無効化する。
- TEST / Preview / Publish 側ではアニメーションを有効にする。

### 今後ヘルプに入れる文言候補

画像が枠だけで表示される場合は、まず下部ステータスを確認する。

- `画像OK` なら画像ファイルは読み込めている。
- `op:0` の場合は、アニメーションや透明度の影響で見えなくなっている。
- 編集画面ではアニメーションを止め、TEST / Preview で動きを確認する。

## 画像読み込みエラーの場合

### 症状

- サムネイルが表示されない。
- 下部ステータスに `画像を表示できません。差し替えてください。` と出る。
- レイヤー一覧に `!` 警告が出る。

### 原因候補

- 画像パスが空。
- 保存データ内の画像参照が切れている。
- Data URL / WebP / PNG の読み込みに失敗している。

### 対処

- 対象レイヤーを選択する。
- 画像メニュー、または背景レイヤーの右クリックから画像を差し替える。
- 差し替え後、警告が消えることを確認する。

## PCでは見える画像がMobileでは見えない

### 症状

- PC側では追加した画像レイヤーが見える。
- PC / Mobile 並べて表示、またはMobile表示に切り替えると、同じ画像が見えない。
- レイヤー一覧には画像レイヤーが存在する。
- 下部ステータスには `共通画像` と表示される。

### 見分け方

画像リンク切れではなく、配置の問題である可能性が高い。

確認ポイント:

- レイヤー一覧に対象画像がある。
- サムネイルが表示される。
- 下部ステータスに `画像OK` と自然サイズが出る。
- PC側では見えるが、Mobile側だけ見えない。

### 原因

PCとMobileは背景・配置を別々に持つ。

そのため、PC側で追加した画像のMobile側レイアウトが、Mobile画面外や見えづらい位置に残ることがある。

これは画像自体の読み込みエラーではなく、PC用配置とMobile用配置が分かれていることによる症状。

### 対処

実装方針:

- 新しく画像を追加した時、PC側だけでなくMobile側にも初期配置を作る。
- PC側の配置比率をもとに、Mobile画面内へ収まる位置へ補正する。
- 既存の共通画像レイヤーがMobile画面外にある場合、再描画時にMobile画面内へ補正する。

### 今後ヘルプに入れる文言候補

PCで追加した画像がMobileで見えない場合は、画像ファイルのエラーではなく、Mobile側の配置が画面外になっている可能性があります。

PCとMobileは別々に配置を持つため、Mobile側で一度位置を調整してください。

## PC / Mobile同時表示で赤ペン指示が崩れる

### 症状

- WITH AIやMarkupの赤ペン指示が、PC / Mobileを並べて表示した時だけ変な位置や大きさで出る。
- PC側にMobile用サイズの赤ペンが出る、またはMobile側にPC用サイズの赤ペンが出る。
- レイヤー名はどちらも `赤ペン指示` のため、見た目だけでは原因が分かりにくい。

### 見分け方

共有状態やレイヤー情報で、赤ペンレイヤーのPC / Mobileレイアウトを確認する。

- PC側レイアウトが `1080x1920` のようなMobileサイズになっている。
- Mobile側レイアウトが `1920x1080` のようなPCサイズになっている。
- `visibilityMode` が `both` のままになっている。

### 原因

PC / Mobile同時表示中に赤ペンを描いた時、赤ペンレイヤーの「描いた側」と「もう片方の画面」のレイアウトが混ざることがある。

赤ペン指示は通常、描いた画面に対する指示なので、PCで描いた赤ペンはPC専用、Mobileで描いた赤ペンはMobile専用として扱う方が分かりやすい。

### 対処

実装方針:

- 新しく作る赤ペン指示は、現在アクティブな画面だけに表示する。
- PCで描いた赤ペンは `desktop`、Mobileで描いた赤ペンは `mobile` の `visibilityMode` にする。
- 既存データでPC / Mobileサイズが逆に入っている赤ペンは、再描画時に自動補正する。

### 今後ヘルプに入れる文言候補

PC / Mobileを並べて表示して赤ペン指示が大きく崩れる場合は、赤ペンが別画面用のサイズで保存されている可能性があります。

一度保存して再読み込み、または最新のTBalanceで開き直すと、赤ペンの表示対象がPC用 / Mobile用に補正されます。

## WITH AI共有失敗 / Failed to fetch

### 症状

- WITH AIで `共有更新` を押すと `共有失敗: Failed to fetch` と出る。
- 共有履歴も `履歴を取得できません` になる。
- TBalance本体の編集画面は普通に動いている。

### 原因

TBalance本体ではなく、WITH AI用のlocalhostブリッジが起動していない、または途中で停止している。

WITH AI共有は `http://127.0.0.1:8787` のローカルブリッジへ状態と画面画像を渡す仕組みなので、ブリッジが止まっているとブラウザ側のfetchが失敗する。

### 見分け方

Codex側で以下を確認する。

- `http://127.0.0.1:8787/api/tbalance/health` が `ok` を返さない。
- `node tools/tbalance/ai-bridge/server.mjs` が起動していない。

### 対処

Codex側でWITH AI共有ブリッジを起動する。

```powershell
Start-Process -WindowStyle Hidden -FilePath "node" -ArgumentList "tools/tbalance/ai-bridge/server.mjs" -WorkingDirectory "C:\Users\kakao\Projects\TeaMerry_Project\WEBSITE（ホームページ）\新HP_Tea Merry Forest"
```

起動後、TBalance側で再度 `共有更新` を押す。

### 今後ヘルプに入れる文言候補

`共有失敗` と出た場合、TBalanceの編集内容が壊れたわけではありません。

WITH AI共有ブリッジが止まっている可能性があります。Codex側でブリッジを起動してから、もう一度共有更新してください。
